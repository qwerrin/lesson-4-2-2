# 4-2-2 課題2: データ処理（CSV ファイルの集計）

AIエンジニア講座 Section 4-2「Python 実践」の実装課題。

## 課題の要件

- CSV ファイルからデータを読み込み、各参加者のスコアの平均・最高点・最低点を算出する
- 結果を分かりやすく表示する

配布された CSV は「名前・日付・科目・スコア」の4列で、参加者5人ぶん40行。

## ファイル

| ファイル | 役割 |
|---|---|
| `score_report.py` | 課題の成果物。CSV を読んで集計し、表で表示する |
| `data/課題2.csv` | 講座から配布されたデータ（1,390 バイト・40 行） |
| `data/欠損サンプル.csv` | 壊れた行の扱いを確かめるための小さなデータ |
| `tests/test_score_report.py` | pytest のテスト（44 件） |

## 実行方法

```powershell
python score_report.py
```

Python の標準ライブラリだけで動くため、追加のインストールは不要。
引数に CSV のパスを渡すと、そのファイルを集計する。

```powershell
python score_report.py data/欠損サンプル.csv
```

## 実装した機能

### 課題の要件

1. CSV を読み込む（`csv.DictReader`）
2. 参加者ごとに平均・最高点・最低点を算出する
3. 桁を揃えた表で表示する

### 追加した機能

4. **科目ごとの集計** — 同じ集計処理を分類キーだけ差し替えて再利用している
5. **全体サマリー** — 最高点・最低点は数字だけでなく「誰の・何の科目・いつ」まで出す
6. **壊れた行の検出と報告** — 空行・欠損・非数値のスコアを飛ばし、何行目をなぜ飛ばしたか最後にまとめて出す
7. **全角混じりでも崩れない桁揃え**
8. **BOM 付き CSV への対応** — Excel が保存した CSV をそのまま読める
9. **エラー終了時は終了コード 1** — ファイルが無い・列が足りない・使える行が1件も無い場合

```
=== 読み飛ばした行（3 件）===
  3 行目: 空行
  4 行目: スコアが数値ではない: '満点'
  5 行目: 名前 が空
```

## 設計で迷ったところ

### 1. 全角の桁揃えに `ljust` は使えない

`str.ljust` は**文字数**で詰める。「山田太郎」は4文字だが、端末では8桁を占める。
半角だけの行と並べると4桁ぶんずれて、表として読めなくなる。

`unicodedata.east_asian_width` が `W`（Wide）か `F`（Fullwidth）を返す文字を2桁として数える。

| 文字列 | 文字数 | 表示幅 |
|---|---|---|
| `abc12` | 5 | 5 |
| `山田太郎` | 4 | **8** |
| `名前A` | 3 | **5** |

### 2. `utf-8` ではなく `utf-8-sig` で開く

Excel が保存した CSV には先頭に BOM が付く。`utf-8` で開くと最初の列名が `﻿名前` になり、
`名前` という列が見つからない。BOM は画面に表示されないので、エラーメッセージを読んでも原因が分からない。

実際に `utf-8` に変えて動かすと、こうなる。

```
ValueError: t.csv に必要な列がありません: 名前（見つかった列: ﻿名前、日付、科目、スコア）
```

「名前が無い」と言いながら「名前」が見つかった列に並んでいる。BOM が無いファイルも `utf-8-sig` で問題なく読めるので、常にこちらを使う。

### 3. 飛ばした行を黙って捨てない

非数値のスコアに出会ったとき、その行を静かに読み飛ばすと **40 件のはずが 38 件で集計されても気づけない**。
平均は「なんとなくそれっぽい値」を返してしまうので、間違いが表に出ない。

飛ばした行は理由と行番号を持ち回して、最後にまとめて報告する。

**ただし報告できない行が1種類ある。** 何も書かれていない完全な空行は `csv.DictReader` が
自分で読み飛ばすため、こちらの処理には届かない。報告に出るのは `,,,` のように区切りだけがある行のほう。
「報告が無い＝全部正常だった」と読まれると困るので、この振る舞いもテストで固定してある。

### 4. 平均ではなく「合計と件数」で持つ

集計値は `Stats(count, total, highest, lowest)` の frozen な dataclass で持ち、平均は都度計算する。
平均を保存する形にすると、行を1つ足すたびに前の平均から元の合計を復元する必要が出る。
`merged_with` は自分を書き換えず、新しい `Stats` を返す。

### 5. 並び順を成績順にしなかった

平均の高い順に並べたほうが「分かりやすい表示」に見えるが、そうしなかった。
集計結果の並びを勝手に変えると、**元の CSV と目で突き合わせて検算することができなくなる**。
`dict` は挿入順を保つので、CSV での初出順がそのまま表の順番になる。

集計値は配布データを手計算した値で固定している（例: 山田太郎は 8 件・平均 83.625・最高 91・最低 75）。

### テストが本当に効くかは、わざと壊して確かめた

| 壊した箇所 | 落ちたテスト |
|---|---|
| `display_width` を `len()` に戻す | 6 件 |
| `utf-8-sig` を `utf-8` に変える | 1 件 |
| 読み飛ばした行を記録せず捨てる | 4 件 |

**1つ目で、通っているのに何も守っていないテストが見つかった。**
最初に書いた表組みのテストは「全行の表示幅が同じか」を `display_width` で測って確かめていた。
検証する側も検証される側も同じ関数を使っているので、`display_width` が壊れると
テストの物差しも一緒に壊れて、**桁がずれた表を「揃っている」と判定して通ってしまう**。

期待する出力を空白の数まで直接書く形に変えたら、同じ破壊で落ちるようになった。

```python
assert table == "\n".join(
    [
        "名前    " "  " "件数",
        "--------" "  " "----",
        "山田太郎" "  " "   8",
        "A       " "  " "  10",
    ]
)
```
